# Command reference

`agent-tools image-prepare INPUT OUTPUT [MAX_DIMENSION] [JPEG_QUALITY]` makes a smaller PNG or JPEG copy using macOS `sips` (default longest edge: 1600 pixels). It refuses to overwrite an existing file. An already-small PNG copied to PNG is preserved byte-for-byte, including metadata; dimensions must be between 1 and 100,000 pixels. Use a smaller dimension for an overview; inspect the original or a crop when text or detail is too small. Image token costs depend on the model and image handling, so savings are not guaranteed.

JPEG quality is optional (1–100); JPEG is lossy and does not preserve transparency. Use the original when small details or transparency matter. The same command can prepare image inputs or generated image outputs.

`agent-tools image-batch OUTPUT_DIR [--max-dimension N] [--format png|jpeg] [--quality N] IMAGE...` prepares several copies and prints JSON with each input/output byte count and byte savings. It refuses existing output names and duplicate basenames. The default is PNG to preserve screenshot detail; JPEG quality is valid only with `--format jpeg`. Conversion requires macOS `sips`; a smaller file is not guaranteed for every input.

`agent-tools image-text IMAGE [--json] [--regions] [--max-chars N]` extracts text locally with macOS Vision. Plain text is the default; `--json` includes source, character count, truncation and empty-result flags. `--regions` also returns each recognized line's text, confidence, and normalized bounding box (`x`, `y`, `width`, `height`) with origin at the top-left. `image-text --batch IMAGE...` processes several images in one process and returns one JSON record per image; a bad image is reported alongside successful results. Output defaults to 12,000 characters per image and can be limited to 1–100,000. Exit 1 indicates empty or truncated output; exit 2 indicates invalid input or OCR failure. OCR may miss or reorder text; inspect the image when accuracy, layout, or visual evidence matters. See [PLAN.md](https://github.com/vystartasv/agent-efficiency-tools/blob/main/PLAN.md) for priorities and measurement.

`agent-tools image-crop INPUT OUTPUT.png X Y WIDTH HEIGHT` extracts a PNG region using pixel coordinates from the top-left corner. The rectangle must be inside the first image frame; the tool rejects non-normalized orientation metadata and existing output paths. It does not resize the region. Inspect the crop before relying on it as evidence: content outside the rectangle is omitted. Requires macOS Swift and ImageIO.

`agent-tools image-diff LEFT.png RIGHT.png [THRESHOLD]` compares equal-sized PNGs with `pixelmatch` and returns changed pixel count and fraction as JSON. Its `pngjs` and `pixelmatch` dependencies are installed with the toolkit. The default threshold is 0.1; antialiased pixels are treated according to `pixelmatch` defaults. Exit 1 means dimensions differ, and exit 2 means the inputs or dependencies could not be processed. Each image is limited to 64 MiB and 16 million pixels. A difference does not prove the intended behavior, and dynamic content or rendering changes can produce noise; inspect the images and their context.

`agent-tools pdf-text INPUT.pdf [FIRST_PAGE [LAST_PAGE]] [--ocr-missing]` extracts selectable text locally using macOS PDFKit. Pages are 1-based; the default is page 1 and a request can cover at most 20 pages. JSON includes the source, total page count, page numbers, text, extraction method, character counts, and flags for missing or truncated text. Text is capped at 12,000 characters per page. `--ocr-missing` locally OCRs up to five pages without a text layer and marks each page's method; further missing pages are flagged as skipped. Exit 1 means text is missing, OCR was skipped, or output was truncated; exit 2 indicates an invalid request or unreadable PDF. OCR can misread text and extraction does not preserve all layout, tables, images, or annotations.

`agent-tools pdf-find INPUT.pdf SEARCH_TEXT` searches selectable text in every page using case-insensitive, non-overlapping literal matches. JSON includes the total match count, up to 20 page-numbered excerpts, and up to 100 page numbers with no extractable text. Exit 1 flags omitted matches or any page with no extractable text; exit 2 indicates an invalid request or unreadable PDF. A page can contain both selectable text and unsearched images, so even a complete result does not prove the phrase is absent from visual content. This command does not OCR or search annotations and can take time on large PDFs.

`agent-tools pdf-ocr INPUT.pdf [FIRST_PAGE [LAST_PAGE]]` renders selected PDF pages locally and recognizes text using macOS Vision. Pages are 1-based, default to page 1, and are limited to five per request. Each page is rendered with a maximum edge of 2,400 pixels; JSON includes the page number, rendered dimensions, text, character count and truncation or empty-result flags. Exit 1 means at least one page had no recognized text or exceeded the 12,000-character output limit; exit 2 indicates an invalid request or processing failure. OCR can miss or misread text, change reading order, and omit diagrams or layout. A nonempty result does not prove completeness. No network upload is performed by this command.

`agent-tools media-info INPUT` returns selected FFprobe metadata for a local file, including available format and stream fields. The result includes the source path, stream count, and a truncation flag; more than 100 streams returns exit 1 with only the first 100. Missing metadata is omitted rather than guessed. Invalid media fails, and probing times out after 30 seconds. FFprobe is required. Use trusted files: media containers can refer to other local files even though network protocols are disabled.

`agent-tools video-frame INPUT OUTPUT.png SECONDS` extracts one frame from a local video using FFmpeg and writes a new PNG without overwriting an existing path. The JSON reports the requested time and, when FFmpeg reports it, the selected frame's normalized presentation time in `frame_time_seconds`; the latter is `null` if unavailable. This is relative to FFmpeg's normalized input timeline, not necessarily the source's absolute timestamp. Variable frame rates and stream timing affect frame selection. An out-of-range timestamp or a file without a video stream fails without creating the output. This inspects one moment only and cannot establish what happened between frames. FFmpeg processes the supplied local file; use trusted inputs, since media containers can reference other local files.

`agent-tools audio-transcribe INPUT MODEL.pt [--language en] [--start SECONDS --end SECONDS]` runs the installed OpenAI Whisper CLI with an explicitly supplied local model file and returns timestamped segments as JSON. It requires `whisper`, FFmpeg, and a compatible local model; the adapter does not download models. Processing may be slow or memory-intensive. Output is capped at 200 segments and 12,000 text characters; exit 1 flags empty or truncated results, and exit 2 flags invalid inputs or unreadable results. The full temporary transcript is deleted; use `--start` and `--end` together to request a smaller time range when output is truncated. Whisper timestamps refer to the original media, but boundaries and recognition are approximate; cutting speech can lose context. Whisper may still decode the full input before selecting the range. Transcripts and timestamps may be wrong, particularly for silence, noisy recordings, multiple speakers, or unfamiliar languages. Use trusted media: FFmpeg may follow references contained in local files.

`agent-tools browser-read URL [MAX_CHARACTERS] [--main] [--wait-for SELECTOR] [--timeout-ms MS]` reads rendered text using a fresh, isolated Playwright Chromium session (default limit 12,000 characters; maximum 100,000). Playwright is installed with the toolkit; Chromium must also be installed. JSON includes title, final URL, HTTP status, selected `content_scope`, total Unicode code points, text, truncation, navigation or selector errors, and a `partial` flag. Exit 1 indicates truncation, an HTTP error, or incomplete navigation/selector wait; any readable partial text remains in the JSON. `--main` selects the first `<main>`, otherwise the first `<article>`, and otherwise falls back to the full body (`scope_fallback: true`). This can omit useful page context; use the default full body when navigation or surrounding content matters. On one synthetic page, this reduced text from 1,016 to 15 `o200k_base` tokens while preserving the seeded version and issue ID; see [the experiment](experiments/RESULTS.md). This is a focused fixture, not a general savings guarantee. It does not use the shared browser's login or inspect accessibility, visual layout, frames or interactions; page scripts and network requests still run. By default extraction starts after `DOMContentLoaded`, so content loaded later may be missing. `--wait-for` waits for the first matching visible Playwright locator; `--timeout-ms` limits that wait to 1–30000 ms (default 5000). A timeout returns any available text with `partial: true`. This does not guarantee that all content has loaded. URLs and returned text can contain sensitive data.

`agent-tools output-capture --output NEW_FILE [--tail-bytes N] [--timeout SECONDS] -- COMMAND ...` saves complete combined stdout and stderr to a new private file, displays a bounded tail, and returns the command exit status. The tail may omit important failures: consult the full file. For focused retrieval, use `rg -n -C 2 -F -- "SEARCH_TEXT" LOG_FILE`; search results may also omit context, so retain the full log. The file may contain sensitive data; choose its location and retention deliberately. Output is displayed after the command finishes. Launch errors are saved in the log; exit 127 means the command was not found and 126 means another launch error. If `--timeout` is set, the command runs in a new process group; exceeding the deadline kills that group, records the timeout, and returns 124. Descendants that deliberately leave the group are not covered. Without `--timeout`, no deadline is imposed.

`agent-tools log-scan INPUT [--pattern REGEX] [--context N] [--max-matches N] [--max-line-chars N]` scans a text log and emits JSON containing matching lines, line numbers and nearby context. The default pattern selects common failure terms; supply `--pattern` when the diagnostic vocabulary is known. It streams the input, returns at most 20 matches and two context lines by default, and caps each line at 2,000 characters. Exit 0 means no matches, exit 1 means matches were found, and exit 2 means the file or request could not be read. A match is a lead, not proof of failure; scan with an explicit pattern or inspect the saved original when completeness matters. On a 5,003-line synthetic log, it reduced a 65,022-token input to a 180-token result while preserving the seeded failure code and expected/actual lines; see [the experiment](experiments/RESULTS.md). The fixture was intentionally simple and the savings apply only when the agent needs the matching diagnostics.

`agent-tools test-report REPORT.xml` extracts JUnit `<failure>` and `<error>` details, including suite-level errors, as JSON with the original report path. Exit 0 means the parsed report contains test cases and no represented failures; exit 1 means failures were found; exit 2 means the report could not be interpreted or declared counts exceed the available details. Empty reports are indeterminate. It does not run tests or establish report freshness, and other diagnostics (such as `system-out`) remain in the original report. Use trusted local reports; extracted details may contain sensitive data.
